# LIFEGRID Demo Sequence

This is a 3–5 minute suggested flow for demonstrating the LIFEGRID platform, highlighting the end-to-end AWS Serverless architecture and local React dashboard.

## 1. Open Dashboard & Show Live Map
- **Action**: Open the React UI (available via local dev server or static hosting).
- **Talking Point**: Start on the **Dashboard**. Explain the "single pane of glass" view.
- **Action**: Navigate to the **Risk Map**.
- **Talking Point**: Show the map interface. The map visualizes synthetic zones and live report clusters.

## 2. Create Emergency Report
- **Action**: Navigate to the **Simulation** or **Reports** tab to create a new report.
- **Data Entry**:
  - **Category**: `Flood`
  - **Severity**: `High (4)`
  - **Affected**: `100` people
  - **Location**: Provide a valid lat/long within a synthetic zone.
- **Action**: Submit the report.

## 3. Show Event-Driven Processing (Backend Flow)
- **Talking Point**: Explain that the API responds immediately (HTTP 201), but the processing is entirely asynchronous.
- **Action**: Open the **Reports** view and look at the newly created report details.
- **Talking Point**: Point out the `event_processing_status`. You will see it shift from `PENDING` to `RISK_ASSESSMENT_PENDING` (and beyond) as the background services run.

## 4. Show Risk Assessment & Resource Requirements
- **Action**: Expand the report details.
- **Talking Point**: 
  - Show the **Risk Assessment** that was automatically generated by the `RiskProcessor` Lambda.
  - Show the **Resource Requirements** (e.g., Water, Shelter) generated by the `ResourceProcessor` Lambda based on the severity and affected count.

## 5. Show AWS Architecture
- **Action**: Open the AWS Console.
- **Talking Point**: 
  - **DynamoDB**: Show the `LIFEGRID-Reports` and `LIFEGRID-ProcessedEvents` tables. Highlight the idempotency ledger that prevents double processing.
  - **EventBridge**: Show the `LIFEGRID-EventBus` and the routing rules that decoupled the risk and resource engines.
  - **Lambda**: Show the microservices (`LifegridApi`, `LifegridRiskProcessor`, `LifegridResourceProcessor`) running efficiently with ~2-3ms execution times.

## 6. Persistence & Final Verification
- **Action**: Refresh the React Frontend page.
- **Talking Point**: Show that data is still present and instantly fetched from the live AWS API Gateway endpoint (`/api/v1/reports`).
- **Conclusion**: The architecture handles ingestion, decoupling, processing, and storage efficiently, entirely using Pay-Per-Request free-tier services.
